# Inflation nowcast

The [inflation watch](https://austinmermans.github.io/public-record/#inflation-watch) shows the [Federal Reserve Bank of Cleveland's Inflation Nowcasting table](https://www.clevelandfed.org/indicators-and-data/inflation-nowcasting): CPI, core CPI, PCE and core PCE for each published target month and year-over-year basis, plus the quarterly annualized table. These are **model estimates**, not BLS/BEA actuals, survey consensus, market-implied rates or trading signals. Monthly change is seasonally adjusted and nonannualized; quarterly change is seasonally adjusted annualized. The publisher uses nonseasonally adjusted CPI and seasonally adjusted PCE for year-over-year estimates.

The public table gives two-decimal percentages and its own update date. A blank cell means the corresponding actual has already been released; Public Record neither turns it into zero nor fills it with an unverified actual. The lead CPI and core PCE cards each select their *own earliest target with a nonblank estimate*, so their target months may differ. A forecast-date change is only compared for the same measure, rate basis and target; a new target is not a month-over-month revision.

For monthly estimates, the [publisher's current chart JSON](https://www.clevelandfed.org/-/media/files/webcharts/inflationnowcasting/nowcast_month.json?sc_lang=en) supplies a target-specific path of dated estimates. Public Record retains only the two target objects currently in the table, with a SHA-256 digest of that excerpt and a separate digest of the complete response at retrieval. It checks chart identity, date sequence, measure labels and the latest value against the two-decimal public table. The plot preserves more precision than the table; headline “last changed” language uses the table's 0.01-percentage-point display precision, so tiny underlying model adjustments do not become a misleading “−0.000” move. The chart's earlier dates belong to the **publisher's current historical edition**, not an archive of its original daily publications. The `_comment` field is an edition date, not an original publication timestamp for every point.

Our separate, append-only captures start when collection starts. Each retains the three exact HTML table fragments—not the full website page—plus their excerpt hash, a full-response hash, source URL and capture clock. The build reparses each retained excerpt and recomputes change events from adjacent verified captures. Only the two relevant chart target objects are retained from the larger JSON feed, rather than mirroring the feed. Source links and the publisher's [reuse terms](https://www.clevelandfed.org/privacy) remain applicable to this third-party material; Public Record's own license does not relicense the source.

The collector runs at most once per scheduled Public Record refresh (currently two refresh opportunities per day, seven days a week). That does not imply the model updates twice a day; the publisher normally updates on business days. If the table fails, the previous verified capture is labeled stale, or unavailable before first success. If chart enrichment fails while the table succeeds, the current table remains usable, its history gap is explicit, and source health is partial. The site is a dated research read, not a live nowcast feed.
